## 1. J3 定速 `ur5_j3_const_velocity_ident.py`（新程式）

### 怎麼看最快

這支是 J2 定速 `ur5_j2_const_velocity_ident.py` 的複本，只改了軸號、姿態、窗口與說明文字。11/12 已用 J2 定速在 UP 上機。以下沒有改：
- 規劃
- 安全檢查
- URScript 產生
- RTDE 記錄
- 分析

兩者的差異約 90 行，看這個就夠：

```bash
diff robot/ur5_j2_const_velocity_ident.py robot/ur5_j3_const_velocity_ident.py
```

### 改了什麼

| 項目 | J2 定速（已審查） | J3 定速 |
|------|------------------|---------|
| `JOINT_INDEX` | 2 | 3 |
| UP 姿態 | (180, −90, **0**, −90, −90, 0) | (180, −90, **0**, **−130**, −90, 0)：J3 從 −90° 轉到 −130°，工具朝前上方約 40° |
| UP 窗口中心 | −5.7°（J2 重力零點） | −131.2°（J3 重力零點） |
| DIAG 姿態 | 診斷原點 | 診斷原點（相同） |
| DIAG 窗口中心 | 71° | −109°（工具往前傾 19°） |
| 安全視窗變數 | `J2_SAFE_MIN/MAX_DEG` | `J3_SAFE_MIN/MAX_DEG`（預設 `None`，沒填就中止） |
| 輸出名稱 | `j2constvel_…` | `j3constvel_…` |
| `KT_OUT`、`GEAR_RATIO` | 13.64、101 | **沿用** 13.64、101（J3 的實際值未知，見下方問題） |

速度級距、加速度、減速度、movej 速度、餘裕、各項上限都和 J2 相同（第 93～114 行）：
- 速度 0.02～0.20 rad/s
- speedj 0.5、stopj 1.0、movej 0.15 rad/s／0.5 rad/s²
- 餘裕 2°，第一次 movej 上限 40°，法蘭最低 0.40 m，法蘭線速度上限 0.25 m/s

### 動作範圍（FULL，不含 2° 餘裕）

| 姿態 | J3 範圍 | 工具方向 | 法蘭高度 | 建議安全視窗 |
|------|---------|----------|----------|--------------|
| UP | −149.91°～−112.49° | 朝前上方 22°～60° | 1.02～1.03 m | −153 / −109 |
| DIAG | −127.71°～−90.29° | 只往前傾，不超過診斷原點 | 0.43～0.51 m | −131 / −87 |

- 法蘭離 J3 軸 0.125 m，最高速度 0.20 rad/s 時法蘭 0.025 m/s，工具尖端約 0.06 m/s。
- 第一次 movej 最遠：UP 13.5°，DIAG 31.3°。
- 跑完 J3 會 movej 回開始角度（UP −130°、DIAG −90°），J2 與 J3 再由人用教導器轉回診斷原點。

### 安全檢查（沿用 J2，未改）

1. 安全視窗沒填，或規劃範圍加 2° 後超出視窗：中止。
2. 法蘭高度低於 0.40 m、法蘭線速度超過 0.25 m/s：中止。
3. 連上 RTDE 後六軸任一軸偏離 `POSE` 超過 ±0.5°（例如忘了把 J3 轉到 −130°）：中止。
4. 教導器負載和 `PAYLOAD_KG` 不符、速度滑桿不是 100%、第一次 movej 超過 40°：中止。
5. 執行前要輸入姿態名稱確認。

### 需要學長確認

1. **UP 姿態把 J3 轉到 −130°**，工具朝前上方約 40°，法蘭約 1.03 m：上方燈具與線架的淨空可以嗎？
2. **安全視窗** UP −153 / −109、DIAG −131 / −87 是否合理？J3 轉動時，手腕線材與相機線會不會被拉扯？
3. **換算比例**：J3 的馬達與減速機比 J0～J2 小，`KT_OUT` 暫用 13.64，B、Tc 先當相對值。
   - DIAG 可以用 target_moment 窗口平均（約 −3.3 N·m）估換算比例。
   - 學長是否知道 J3 的馬達轉矩常數或減速比？減速比 101 也是沿用，分析時會看電流漣波是否鎖定在 101 × 關節角。
4. **速度級距**：J3 慣量與重力都小（重力最大約 3.6 N·m），速度級距與加速度沿用 J2，可以嗎？

## 2. J1 速度調變 `ur5_j1_velocity_modulation_ident.py`：低頻條件組 `LOWF`

### 改了什麼

新增設定 `CONDITION_SET`（第 101～110 行），預設 `"STD"`。

- **`STD` 和 11/5、11/12 跑的完全相同**，包括條件、調變時間 3 s 與資料夾名稱。
- 改成 `"LOWF"` 時，條件如下表，調變 4 s：

| 條件 | f [Hz] | 速度振幅 [rad/s] | 加速度振幅 [rad/s²] |
|------|--------|------------------|---------------------|
| 1 | 1.0 | 0.04 | 0.25（= STD 條件 1） |
| 2 | 0.5 | 0.05 | 0.16 |
| 3 | 0.75 | 0.05 | 0.24 |
| 4 | 1.5 | 0.0265 | 0.25 |
| 5 | 2.0 | 0.02 | 0.25 |

程式上的改動：
- 新增 `condition_set()`。
- `stage_config()` 多一個參數。
- `main()` 改用所選條件組的條件與調變時間。條件組名稱錯誤時中止。
- 資料夾名稱多 `lowf_`，摘要檔記錄條件組。

**規劃、安全檢查、URScript 都沒改。** LOWF 一樣經過原本的安全檢查：
- 速度上限
- 最低速度 0.03 rad/s（速度不歸零、不反向）
- 調變加速度上限 1.5 rad/s²
- 安全視窗
- 法蘭高度與線速度

### 動作範圍（UP、FULL，每個方向 35 段、約 5.2 分鐘）

- 調變段長 18.33°（STD 為 13.75°），所以範圍比 STD 大。
- 正轉 −106.73°～−79.82°，反轉 −104.18°～−77.27°。
- 含 2° 餘裕後在安全視窗 −114 / −70 內，仍在 J1 定速 FULL 跑過的範圍內。
- 法蘭最低 0.96 m，線速度最高 0.14 m/s。

### 需要學長確認

1. **0.5 Hz 是否保留**：0.5 Hz 時重力造成的假慣量約 +7 kg·m²，比 J 本身（約 6）還大，結果非常依賴重力項，只能當參考。拿掉的話 FULL 可省約 1 分鐘。
2. 調變段比 STD 長 4.6°，J1 擺動範圍比 11/12 大一些（仍在 −114 / −70 內），可以嗎？
